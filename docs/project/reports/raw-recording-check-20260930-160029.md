## 统计口径与限制

- pose 帧率 = (样本数 − 1) / 首末 header 时间差；按整数纳秒做差，避免 Unix 秒转浮点带来的精度损失。
- 视频帧率 = (解码帧数 − 1) / 首末真实 PTS 时间差；不是单独读取 MP4 声明帧率。
- 将每帧 PTS 加到 timing 中的 first_receive_unix_ns，逐帧比较 pose header 范围。六路全部覆盖；首末源 PTS 跨度与 MP4 PTS 跨度相差不超过 0.167 ms。
- 大间隔阈值为目标周期的 1.5 倍：pose 16.667 ms，image 50 ms。5/3/2 是双周期间隔事件数；估计缺少更新不等于已证明硬件或写盘掉帧数。
- 该 session 未做逐路时间差标定。覆盖结论使用主机接收时间与源 PTS，未验证真实曝光时刻及校正后的覆盖。
- MP4 中没有 >50 ms 间隔、且解码数等于录入数，支持没有明显图像掉帧迹象；没有保存相机原生逐帧序号，source_completeness 仍为 not_verified。
- 正式录制日志确认真实 Tracker 源节点和独立 30 Hz Path 节点均启动并干净退出；原始文件不保存 Path，不能据此确认 Path 的实际帧率或 RViz 渲染表现。
- 本检查为用户指定的一次验收，不新增逐条 pose 自动检查或改写原始录制 JSON。

程序读取 MCAP 和解码六个视频的统计耗时约 1.985 秒（不含准备与报告整理）。
